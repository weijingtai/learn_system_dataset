# OPERATOR_MANUAL：人工管理手册 v1.0

> 读者：你（项目唯一的人工操作员）。
> 处理单位：**一本典籍**。从找到它，到它变成可检索、可引用的知识，全流程十步。
> 你不需要写代码。每步写明：你做什么、AI 做什么、完成标志、常见坑。给 AI 的指令直接复制用。

## 第 2 章 十步详解

### 第 1 步：选书立项（你）

1. 打开 `registry/`，看这本书是否已有档案（避免重复）；
2. 没有就复制 `registry/works/_TEMPLATE.yaml` 建一份，填書名、技法、为什么选它、优先级；
3. 判断一句话就够的立项标准：**这本书能为已定的高频问题提供出处吗？** 不能就先不做。

完成标志：`registry/works/` 下有档案，status 填 `selected`。
常见坑：因为"有名"而选书。名气不等于对当前词条有用；《四库》里术数书几百种，全按名气排队做不完。

### 第 2 步：找底本（你＋AI 查询辅助）

从第 6 章的可信来源找扫描件或已数字化文本。优先顺序：

1. **有可靠电子文本**（识典古籍、ctext、Kanripo）→ 下载文本＋对应影像，AI 只做核对，最省钱；
2. **只有扫描影像** → 下载影像，走 OCR（第 3 步全流程）；
3. **只有网络流传的整理 txt** → 只可参考，**不可作底本**（校勘与权利都不明）。

拿到文件后交给 AI 的指令：

> 把 `<下载目录>` 里的文件登记进 corpus：建 `corpus/<技法>/<书名>/raw/`，原样存放，生成 manifest.yaml（含每个文件的 sha256、来源 URL、下载日期、rights_status）。不要改动任何原始文件。

完成标志：manifest 存在、哈希齐全、rights_status 不是 unknown（unknown 会被校验阻断——这是故意的，逼着把权利问题在入口解决）。
常见坑：影像是公版 ≠ 平台允许转用其整理文本。**影像底本尽量选公版原书扫描；他人整理的标点/校勘文本要单独确认条款**（HANDBOOK 工位 0 的 RightsGrant 原则）。

### 第 3 步：数字化（AI）

分两种情况给指令：

**情况 A：有电子文本＋影像**

> 按 HANDBOOK 工位 1 规程，将 `raw/` 中的电子文本与影像逐页核对，产出 `source/transcript_v1.md`（页边界标记 `<!-- p00NN -->`），差异处以影像为准并记入 uncertainties，疑难字标 `⟦?⟧`。禁止改字、简化、补字。

**情况 B：只有影像（需 OCR）**

> 对 `raw/` 影像逐页 OCR（繁体竖排优先用支持古籍的引擎），产出初稿后按 HANDBOOK 工位 1 规程自行与影像核对一遍，然后输出 transcript_v1.md，规则同上。

完成标志：transcript 存在、页码标记连续、AI 的 result.yaml 里 uncertainties 每条都有页码。
你的抽查（10 分钟）：随机挑 2 页，对着影像看转录，发现**一处**擅自改字 → 整步打回（不是修那一处——一处被发现意味着还有没被发现的）。

### 第 4 步：结构盘点（AI）

> 按 HANDBOOK 第 4.1 节对 transcript 做结构盘点，产出 outline.yaml：每个叶子节点 ≤ 一个自然结构单元，标注页码范围和文本类型（A 韵文/B 论说/C 条目/D 注疏混排）。

完成标志：outline 覆盖全书页码、无重叠无缺口。
你看一眼（5 分钟）：目录层级是否和你对这本书的印象一致；类型标注是否离谱（比如把《穷通宝鉴》的条目标成散文）。

### 第 5 步：分批建任务包（AI）

> 按 HANDBOOK 第 4.2/4.3 节，从 outline 生成批次账本 batches.yaml 和前 3 个批次的任务包（每包含 input/text.md、context_before.md、path.txt、glossary.yaml、INSTRUCTIONS.md、task.yaml 含 id_range）。只建前 3 批。

**只建前 3 批**是纪律：模板有问题时，跑得越多废得越多。

### 第 6 步：流水线跑批（AI，你只管 ESC）

> 对 batch_001 依次执行：切分（工位 3）→ 术语（工位 4）→ 主张双路提取（工位 5，DeepSeek 与 GLM 各一遍）→ 比对分歧 → 白话释义（工位 6）。每工位完成即跑校验，PASS 才进下一工位。分歧和拿不准的按 HANDBOOK 2.2/2.3 出 ESC。

你的工作：每天看一次 `escalations/` 目录，每个 ESC 是一道带选项的选择题，选完即可。攒着不答会阻塞对应条目（但不阻塞其他批次）。

### 第 7 步：抽查签发（你，每批 10–20 分钟）

AI 会给你生成一页抽查单（每批抽 10%，至少 5 条），你对每条回答三个问题：

1. 引文和出处页码对得上吗？（点开影像看）
2. 主张是原文说的吗？有没有 AI 自己加的话？
3. 条件（月令、旺衰、"若/凡/惟"）都带上了吗？

三问全过 → 勾；任一不过 → 记下条目号。**一批错误 ≥ 2 条 → 整批打回重做并让 AI 修订该批的任务模板**；只错 1 条 → 修那一条，批次通过。

### 第 8–9 步：编译词条＋重建检索（AI）

> 按 HANDBOOK 工位 9 聚合词条；然后按 RAG_GUIDE 重建索引并跑完验收测试，把测试结果贴给我。

完成标志：`rag/query.py locate` 能查到这本书的句子。

### 第 10 步：归档收尾（你，5 分钟）

1. `registry/works/<书>.yaml` 状态改 `compiled`，填一句话总结（质量如何、坑在哪）；
2. 本书遇到的新问题和解法，让 AI 追加到档案的 `lessons` 字段——**这是下一本书省时间的关键**。

## 第 3 章 遇到未知问题的解决思路（四步法）

技法几百种、流派无数，你不可能都懂。遇到没见过的问题，按固定顺序走：

**第 1 步：归类。** 所有问题只有四类，每类有默认动作：

| 类别 | 例子 | 默认动作 |
|---|---|---|
| 权利/来源 | 这个平台的文本能商用吗？ | 未确认 = 不用。找公版影像替代 |
| 技术/格式 | 竖排双行小注 OCR 全乱 | 切小样本让 AI 试 2–3 种方案，选最好的 |
| 术义/内容 | 这句两派读法不同 | 不裁决。disputed 并列保留——本系统天生允许存疑 |
| 流程/工具 | 校验程序不适配新情况 | 让 AI 提方案，你确认后改工具，**不为过工具而放松标准** |

**第 2 步：查档案。** `registry/` 和 `escalations/` 里搜关键词——很多"新"问题以前遇过。

**第 3 步：最小试验。** 切最小的一片（几页、一个条目）做实验。**永远不拿整本书赌一个没验证过的方案。**

**第 4 步：把答案写回档案。** 让 AI 把结论追加到对应 registry 条目的 `lessons`。未知问题只允许每个坑掉一次。

一条心法：**这个系统的设计本来就假设"不知道"是常态**——disputed、needs_expert、blocked、ESC 全是为"不知道"准备的容器。遇到不懂的，放进容器继续走，而不是停下来假装必须先懂。

## 第 4 章 档案系统 registry/

三种档案，模板在 `registry/` 各子目录的 `_TEMPLATE.yaml`：

```
registry/
├── techniques/   技法档案（奇门、八字、六爻……一技一档）
├── schools/      流派档案（归属某技法）
└── works/        典籍档案（归属某技法，可标流派倾向）
```

档案是**给人看的摘要＋给 AI 查的事实**，每条不超过一屏。状态流转：

```
works:      candidate → selected → sourcing → digitizing → processing → compiled → archived
techniques: observed（知道存在）→ profiled（已立档）→ active（正在做）
```

已建示例：`registry/techniques/qimen.yaml`、`registry/works/yanbo_diaosou_ge.yaml`。新增档案照模板抄。

## 第 5 章 可信书源清单

按"优先用"排序。共同注意事项：**影像底本的原书多为公版，但"平台整理的文本"权利各异，用前逐平台确认**（这就是第 2 步 rights_status 不许填 unknown 的原因）。

| 来源 | 有什么 | 怎么用 | 权利注意 |
|---|---|---|---|
| 中华古籍资源库（中国国家图书馆） | 十万部级善本影像，含子部术数类 | 网页免登录浏览 | 公版影像；批量下载看站内条款 |
| 识典古籍（字节＋北大） | 整理后文本＋影像对照，OCR/标点质量高 | 网页检索阅读 | **文本转用条款必须单独确认**；影像对照可用于核对 |
| 中国哲学书电子化计划 ctext.org | 大量子部文本＋部分影印对照，有 API | 检索、对照、API 取文本 | 用户参与校对，引用前须对影像核字；条款允许学术使用，商用需确认 |
| Kanripo 汉籍リポジトリ | 开放的结构化汉籍全文（GitHub 仓库，KR 编号） | `git clone` 对应仓库，KR3（子部）含术数 | 开放许可，底本信息随库注明——最适合程序化处理 |
| 早稻田大学图书馆古典籍数据库 | 高清扫描，和刻本汉籍多 | 网页下载 PDF | 公开下载，注明出处 |
| 日本国立国会图书馆数字馆藏 | 大量汉籍影像 | 网页浏览/下载 | 按藏品页标注的许可 |
| Internet Archive | 各类影印本（含《四库全书》影印、民国印本） | 检索下载 | 逐件看权利标注；现代影印本的版式权归出版社 |
| 影印丛书（文渊阁四库·子部术数类、续修四库、《古今图书集成·艺术典》） | 术数典籍最集中的成体系来源 | 通过上述平台找对应影像 | 原书公版；只用扫描影像，不用出版社新排文本 |

**避开**：论坛/网盘流传的"整理版 txt/pdf"——校勘质量不可考、权利不明，只能当"找原书线索"用，不得进 corpus。

## 第 5A 章 文件格式入库对照表【2026-07-11 新增】

铁律：**分析模型只接受标准化的 transcript 纯文本**。任何格式先在入库层转换，原始文件原样存 raw/ 记哈希；转换用确定性脚本（禁止让模型"帮忙转换"——它会顺手改字）；转换工具与版本记入 manifest。

| 来源格式 | 转换路线 | 注意的坑 |
|---|---|---|
| TXT（无格式） | 检测编码（UTF-8/GBK/Big5）→ 统一转 UTF-8 → transcript | 编码猜错会出乱码；段落边界可能是硬换行，结构盘点时重建 |
| EPUB | 本质是 zip 里的 XHTML：解包 → 按 spine 顺序抽正文 → 去 HTML 标签、保留章节标题作标记 → transcript | 脚注/夹注常以 `<sup>`/链接形式存在，剥标签时最易丢——转换后必查；封面/版权页/广告页要剔除并在 manifest 说明 |
| MOBI/AZW | 先用 Calibre 的 `ebook-convert` 转成 EPUB 或 TXT，再走上面两条路线 | 转换器版本记录进 manifest；DRM 文件不收 |
| CSV/表格 | 不走 transcript——按类型 C 直接结构化：每行一条目，**保留原表头字段名** | 这是 HANDBOOK 3.2 的场景；表头语义不明时先出 ESC，不猜列含义 |
| PDF（文字层） | 抽文字层 → transcript；无文字层按扫描件走 OCR（工位 1 情况 B） | 文字层顺序可能乱（双栏排版），抽出后对照原 PDF 抽查页首页尾 |
| 网页/HTML | 同 EPUB 路线（本质相同） | 去广告、导航等噪音，保留正文与注释结构 |

一句话总结：**格式多样性是入库层的问题，不是模型的问题**——模型的世界里永远只有一种输入。

- 每天：清一次 `escalations/`（通常几分钟）；
- 每批完成时：做第 7 步抽查（10–20 分钟）；
- 每周：看一次各书 batches.yaml 进度＋registry 状态，决定下一本书或下一批；
- 永远不做：替 AI 干活（逐条整理）、跳过抽查直接放行、在 rights_status 未确认时开工。
