# Subagent 工作包准出与验收规范

状态：最终规范（用户于 2026-09-09 确认启用）
日期：2026-09-09

## 1. 职责边界

主 Agent 不执行业务代码实现。主 Agent 负责把每个工作项准备到可机械执行状态，生成派发 Prompt，并在执行 Agent 完成后独立验收。

```text
主 Agent：规格 → BDD → TDD → ACT → ACT审查 → Executor Prompt
执行 Agent：严格按工作包实现、测试、提交、报告原始证据
主 Agent：范围核对 → 重跑门禁 → 规格审查 → 质量审查 → 勾选完成
```

架构文档、Schema、测试、代码、数据迁移均适用本规范。主 Agent 可以修改规划、验收和工作包文档，但不代替执行 Agent 完成工作包中的实现任务。

## 2. 每个工作项的标准目录

从本规范生效后，新派发工作项统一放在：

```text
docs/blackbox-spec-rework/work-items/<task-id>/
├── README.md       # 目标、背景、依赖、范围、禁止项、基线
├── BDD.md          # Given/When/Then 可观察行为
├── TDD.md          # 先红后绿用例、命令和期望输出
├── ACT.yaml        # 30–60 分钟粒度机械指令
├── PROMPT.md       # 可直接发送给执行 Agent 的完整 Prompt
└── ACCEPTANCE.md   # 主 Agent 验收步骤与证据模板
```

一个大项需要多个独立提交时，可以使用 `act/01.yaml`、`act/02.yaml`，但必须在 README 中声明顺序和 `DEPENDS_ON`。不得用一个 ACT 同时修改彼此无关的子系统。

## 3. 准入与准出

### 3.1 PREPARING 准入条件

- 有唯一 `task_id` 和权威需求来源；
- 前置依赖明确，没有未声明的循环依赖；
- 当前分支、工作树、已知失败和基线命令已记录；
- 已确认该任务应由执行 Agent 完成，而不是仍需用户拍板的设计问题。

### 3.2 READY 准出条件

只有同时满足以下条件，主 Agent 才能生成并交付 Executor Prompt：

1. README 明确 Goal、Scope、Forbidden、Inputs、Dependencies 和 Stop Conditions；
2. BDD 覆盖正常、失败、空输入或缺失依赖、回归风险；
3. TDD 给出先红后绿顺序、精确测试文件、命令、退出码或期望输出；
4. ACT 的读写路径真实存在或明确标为新建，单项规模为 30–60 分钟；
5. ACT 不新增**未经批准**的依赖、不改变验收标准、不要求执行者自行设计；依赖若用于替代自研基础能力，必须由主 Agent 在工作包中记录选型依据、精确版本范围、离线失败策略和唯一使用边界；
6. ACCEPTANCE 能区分既有失败与本任务新增失败；
7. `wjt-react` 四查结论为 `READY`；
8. PROMPT 包含工作包路径、允许范围、禁止范围、验证命令、提交要求和最终证据格式。

未达到 READY 的工作项不得派发。普通自然语言说明不能替代工作包。

## 4. BDD 与 TDD 的适用方式

BDD 只描述可观察结果，不写实现方法。代码任务从用户或系统行为观察；文档和 Schema 任务从消费者、验证器或执行 Agent 能否得到唯一解释观察。

TDD 不等于所有任务都必须写业务单元测试：

- 代码任务：必须先写失败测试，再做最小实现；
- Schema：先准备应通过和应失败的 fixture，再写或补 Schema；
- 文档规格：先写会失败的结构、枚举、交叉引用或冲突扫描命令；
- 纯迁移：先记录数量、哈希和冲突基线，再执行复制或转换；
- 删除或依赖清理：先证明零引用或建立会失败的构建门禁。

任何仅检查标题、文件存在或固定字符串、却不能证明语义的测试，都不能单独作为通过依据。

## 5. 执行 Agent 交付要求

执行 Agent 必须：

- 只修改 ACT 的 `SCOPE.WRITE`；
- 不修改验收标准、BDD、ACT 或准出门禁；
- 遇到歧义、新失败或需要扩大范围时停止并报告；
- 每个 ACT 独立提交；
- 报告 commit、实际修改文件、测试原始摘要、跳过项和剩余风险；
- 不把 subagent 自己的汇报视作验收通过。

## 6. 主 Agent 验收与完成条件

主 Agent收到交付后依次执行：

1. 对比声称文件与真实 `git diff --stat`；
2. 扫描 Forbidden 路径和禁止模式；
3. 重跑 ACT 与 TDD 的精确命令；
4. 检查测试是否存在空断言、跳过分支、永真条件或只在 Fake 路径通过；
5. 进行规格符合性审查；
6. 规格通过后再进行质量审查；
7. 所有问题必须返给执行 Agent 修复并重新审查；
8. 保存最终证据，更新 PLAN、HANDOFF 和 `SUBAGENT_TODO.md`。

只有主 Agent可以把工作项总项勾选为完成。执行 Agent 完成实现不等于验收完成。

## 7. 状态

| 状态 | 含义 |
|---|---|
| `BACKLOG` | 已登记，尚未准备工作包 |
| `PREPARING` | 正在编写 BDD/TDD/ACT/Prompt |
| `READY` | 工作包通过 ACT 审查，可以派发 |
| `DISPATCHED` | 已交给执行 Agent |
| `REVIEWING` | 已收到实现，正在独立验收 |
| `ACCEPTED` | 全部门禁通过，证据已落盘 |
| `BLOCKED` | 有明确依赖、用户决策或连续失败阻断 |
