## 1. 产品目标

用户能够阅读原书、选择原句写注解，也能独立编写 Markdown 笔记。内容默认私密，可端到端同步并选择加密云备份；用户明确发布后，其他人可阅读、评论、回复和互动。原书阅读与知识 Tooltip 查询同一组关联内容和讨论。

成功不是界面按钮齐全，而是保存可恢复、发布权限有效、历史可追溯、通知可送达、原句可准确定位。用户内容不直接改变官方知识、证据或发布资格。

## 2. 用户与身份

- 本人：管理私人内容、修订历史、备份、发布状态和回收站。
- 其他账号：阅读允许公开的内容、互动、举报或通过已有 IM 联系作者。
- 宿主审核角色：沿用既有权限隐藏/恢复违规公共内容，不获取私人备份解密权。
- 复用宿主账号与登录系统；公开身份为可追溯账号昵称，不支持匿名发布，不要求将私人内容公开。
- 已授权账号可离线编辑；登录过期、账号切换、设备吊销不得导致跨账号读取或发布。

## 4. 本期撤销、重做与键盘边界

| 平台 | 撤销 | 重做 |
|---|---|---|
| Windows/Linux | Ctrl+Z | Ctrl+Shift+Z 或 Ctrl+Y |
| macOS | ⌘Z | ⌘⇧Z |
| 手机/平板 | 撤销按钮 | 重做按钮 |

本期提供 Undo/Redo 编辑动作及上述平台按键映射。按钮在无可操作历史时禁用。

- 连续输入合理归组；粘贴、格式、图片插入各自构成完整操作。
- 中文输入法组合过程作为整体，不逐个拼音键拆分历史，不拦截输入法正在使用的按键。
- 自动保存不清空撤销栈；撤销后新增编辑清空原重做分支。
- 撤销只改变当前编辑内容；保存后生成新的持久修订，不删除过去的审计历史。
- 撤销不执行“撤回发布”、删除云备份等远端业务命令。撤销图片引用不立即删除仍被历史版本引用的图片。
- 本期不跨重启持久化撤销栈；重新打开使用持久历史恢复旧版本。
- **完整键盘操作设计当前缺失并明确后置**：不在本期设计或承诺其他自定义快捷键、快捷键配置及跨页面键盘导航方案。保留平台普通输入行为，不禁用现有系统能力。

## 5. 已定案的默认规则

| 事项 | 本期规则 |
|---|---|
| 自动保存 | 2 秒去抖；失焦/返回尝试立即落盘；有效内容变化才新增修订 |
| 历史展示 | 编辑会话归组，支持逐修订查看差异；不会覆盖持久版本 |
| 冲突 | 保留双方版本；选择/手动合并产生新修订，不做实时多人协同 |
| 云备份 | 首次明确选择，启用后自动；关闭/删除分开 |
| 回收站 | 30 天；恢复仍私密；到期及彻底删除进入可重试清理流程 |
| Markdown | 源码编辑、预览、工具栏、图片、撤销重做、历史；通用附件后置 |
| 排序 | 一级默认最新，可最早；楼内时间正序；无热度推荐算法 |
| 通知 | 评论/回复/@ 必须进入通知管线，按既有拉黑/偏好处理投递；赞进入站内通知，系统提醒遵守偏好；踩/收藏/分享默认不通知 |
| 公开离线 | 不承诺完整公共离线阅读；重连核验可见性；服务端确认后才报告公共写入成功 |
| 审核 | 复用举报、拉黑与人工处置；不新增自动审核服务 |

已公开过的内容无法从他人截图或合法离线副本中远程抹除。收回承诺为阻止新的服务端访问和在线视图失效；不能一边发永久公开图片 URL，一边承诺立即撤权。

### 5.1 不可逆与高影响动作的确认规范

以下动作执行前必须展示确认层，内容三段式：**将要发生什么 / 影响哪些数据（带真实数量）/ 能否撤销**。仅有「确定/取消」的通用对话框不满足验收；文案中的数量必须是运行时真实值，测试断言不得出现「N 篇」这类未替换占位符。

| 动作 | 确认层必须包含 |
|---|---|
| 彻底删除 | 「将永久删除《标题》及其 N 个历史版本、M 张图片，并从云备份中一并清除。此操作无法撤销。已被他人保存的公开副本无法收回。」需二次点击确认 |
| 删除云备份 | 范围（N 篇笔记 / M 张图 / 约 X MB / 最早备份时间），且显式说明「本机数据不受影响」 |
| 关闭云备份 | 「已备份的内容仍保留在云端，如需删除请另行操作」，并提供跳转到删除入口的链接 |
| 收回发布 | 「N 人的评论将无法访问，你的私人稿件与历史不受影响；已被截图或离线保存的内容无法收回」，并说明可再次发布 |
| 拉黑 | 双向影响范围与解除入口位置 |

首次发布额外展示一次性后果说明：「发布后其他人可以阅读、评论并保存副本；即使之后收回，已被保存的副本无法收回。」这条对应 §5 末段的技术事实，必须在动作发生前告知用户，不能只写在文档里。

## 6. UI 与用户旅程

1. 我的笔记列表 → 新建 → 编辑/预览 → 本地保存 → 查看历史；显示本地、设备同步、云备份三个状态。
2. 原书阅读（正文按页边标记显示哪些句子已有公开讨论及其条数）→ 选文字 →（若该文本在当前版本有多处匹配，先在带上下文的候选列表中确认位置）→ 新建私密注解或查看公开注解 → 打开讨论 → 回复/@ → 接收方从通知返回同一楼内回复。
3. 私人笔记 →「发布」→ 发布预览页（显示将发布的修订时间与摘要、包含的 N 张图片及各自就绪状态、可就地切换到其他已保存修订）→ 首次发布展示一次性后果说明（§5.1）→ 确认发布 → 成功页提供「查看公开效果（他人视角）」与「返回笔记」→ 编辑私人草稿 → 更新发布或收回。任一图片未就绪时发布按钮禁用，预览页在该图位置显示具体原因（上传中 x% / 上传失败 / 文件已丢失）与对应动作（等待 / 重试 / 移除该图）；取消预览返回编辑页且未保存内容不丢失。
4. 内容详情 → 资料 → 沿用宿主关注/私信流程；举报/拉黑影响后续交互与通知。
5. 我的笔记 → 移入回收站（显示「剩余 N 天」）→ 恢复或彻底删除；待撤公开、待清理、清理失败可区分，且各自有对应的用户动作。
6. 冲突：笔记列表出现「另一台设备有不同版本」标记 → 打开笔记，顶部横幅提示，正文默认展示本机版本且**可正常继续编辑** → 点击横幅进入对照页（左：本机 / 右：<设备名> <时间>）→ 选择「保留本机」「采用对方」「手动合并」或「稍后处理」。选「稍后处理」后可继续输入与自动保存，横幅保留但不再自动弹出；三个处理选项均生成含双 parent_ids 的新修订，未被采纳的分支在历史页仍可查；合并编辑区支持 §4 定义的撤销/重做；提交前收到第三条分支时不覆盖用户正在编辑的合并稿。
7. 首次开启云备份：设置 → 云备份 → **后果说明页**（内容加密后上传 / 我们无法解密也无法帮你找回 / 必须自行保存恢复材料；含「若丢失恢复材料，已备份内容将永久无法打开，任何人包括我们都无法帮你恢复」字样，该页不可跳过，关闭即不开启）→ 生成并展示恢复材料（提示截图与云剪贴板风险）→ 「复制」/「保存为文件」→ **回填验证**（重新输入其中若干位）→ 验证通过才真正启用。未通过回填验证前备份不启用，返回时提示「备份尚未开启」。**恢复材料支持事后重新导出**：设置中提供「查看恢复材料」入口，需当前设备处于已授权状态并通过本地生物识别或设备密码二次验证。
8. 全部旧设备丢失后的恢复：新设备登录 → 检测到云端备份 → 「检测到 <时间> 的备份，需要恢复材料才能打开」→ 输入 → 恢复进度（N/M 篇）→ 完成。输入错误只提示「恢复材料不正确」，不提示错在第几位或还差多少；恢复中断后重进可从中断处继续，不产生半份数据；选择「暂不恢复」时告知「云端备份仍保留，可稍后在设置中恢复」，并说明此时在本设备新建笔记不会覆盖或作废云端备份。
9. 待处理队列：「我的」→「待处理」列出所有尚未被服务端确认的公共操作（发布、更新发布、收回、评论、回复、举报），每条显示目标、内容摘要、发起时间、当前状态与可执行动作（重试 / 取消 / 复制正文）。因目标被删除、被收回、被拉黑或权限变更而终止的操作，必须产生用户可见提示且**正文可复制**，不得静默丢弃；为空时显示「所有操作都已完成同步」。

原书、注解、笔记交付正式 Flutter UI；Tooltip 交付真实链路原型及 UI 调用协议，不交付占卜模块里的最终嵌入 Widget。加载、空态、离线、失权、保存失败、冲突和重试均纳入界面验收。

### 6.1 三个保存状态的取值与呈现

每条笔记在列表与编辑页显示三个独立状态指示，取值互不共用文案，不得用「—」或空白代替：

| 维度 | 取值 | 用户可见含义 | 用户可执行动作 |
|---|---|---|---|
| 本地 | 未保存 / 保存中 / 已保存本机 / 保存失败 | 这台设备上会不会丢 | 保存失败：立即重试、复制全文 |
| 设备同步 | 未开启 / 无其他设备 / 同步中(n/m) / 已同步至 k 台 / 同步失败 / 对方版本待处理 | 我的其他设备拿到没有 | 失败：重试；待处理：进入旅程 6 |
| 云备份 | 未开启 / 排队中 / 上传中(x%) / 已备份至 <时间> / 备份失败 / 状态未知（离线） / 已关闭（存量保留） | 设备全丢时能否找回 | 未知：显示最后一次已知成功时间；失败：查看原因并重试 |

- 断网时云备份维度必须显示「状态未知（离线），最后确认备份时间 YYYY-MM-DD HH:mm」，不得显示「已备份」，也不得空白。
- 从未开启云备份的账号显示「未开启」并可点击进入旅程 7，不使用失败样式。
- 任一维度为失败态时，列表项须有不依赖颜色的可识别标记（图标 + 文字），灰阶下仍可区分（A11Y-08）。
- `saving` 持续不足 400 ms 时不显示中间态，避免高频闪烁。

### 6.2 用户可见状态词表（封闭集合）

实现不得自造同义词。内部枚举保持英文，展示层只用本表词汇。

| 内部组合 | 作者看到 | 他人看到 |
|---|---|---|
| never_published + active | 仅自己可见 | 无入口 |
| published + active + allowed 且 head ≠ 已发布修订 | 已公开 · 有未发布的修改 | 当前公开版本 |
| withdrawn（服务端已确认） | 已停止公开 | 该内容已不可访问 |
| 本地已发起收回、服务端未确认 | 正在停止公开，他人可能仍可访问 | 当前公开版本（仍可读） |
| published + hidden | 已被管理员暂停展示（附申诉入口） | 该内容已不可访问 |
| trashed | 在回收站 · 剩余 N 天 | 该内容已不可访问 |
| purge_pending | 正在彻底清除 | 无 |
| purge 失败 | 清除未完成 · 点此重试 | 无 |

- 离线点击删除一篇已公开的笔记，作者视图必须出现「正在停止公开，他人可能仍可访问」，禁止任何完成时态表述；收到服务端确认后同一位置自动更新为「已停止公开」，无需手动刷新。
- **内容失效对他人一律使用统一文案「该内容已不可访问」，不区分收回/删除/被隐藏/被拉黑四种原因，响应体不得包含可区分原因的字段**（R-20 决策项，2026-09-10 用户确认）。作者本人视角的「已被管理员暂停展示」是唯一例外，仅对作者可见。

### 6.3 等待、进度与规模

任何预期超过 1 秒的操作显示进行中指示；超过 5 秒显示可量化进度（百分比或 n/m）；超过 30 秒允许用户离开当前页而操作在后台继续，并在完成/失败时给出应用内提示。

- 预览渲染：超过 256 KiB 的 Markdown 采用渐进渲染，首屏 1 秒内可见且不阻塞输入；以 1 MiB 上限文档验证输入区在渲染期间仍响应按键。
- 图片上传：显示 n/m 与当前文件进度，允许取消；单张失败不使整批作废，失败张可单独重试；20 张上传中断第 12 张后重进，前 11 张不重传。
- 云备份：显示 n/m 与剩余量，可离开设置页后台继续，完成与失败各一次应用内提示；需提供「仅 Wi-Fi 备份」开关并在首次开启时告知流量影响。
- 书籍导入：显示阶段（校验中 / 装载中 / 激活中）与进度，允许离开；失败时明确告知旧版本仍可正常阅读。
- 讨论区分页：一级默认 20 条、楼内默认展开 5 条，加载更多期间已有内容与滚动位置不跳动。

### 6.4 七状态必答矩阵

本期所有列表与详情页沿用 `knowledge_system/METAPHYSICS_KNOWLEDGE_COMPILATION_WORKFLOW_v1.2.md` §11.3 的七状态必答矩阵（LOADING / EMPTY / PARTIAL / ERROR / OFFLINE / STALE / SUCCESS），逐屏给出答案，缺任一状态视为该屏未完成。涉及的屏至少为：笔记列表、公开注解列表、讨论区、回收站、通知、历史差异、@ 候选、待处理队列、备份设置。

- 笔记列表首次为空：说明「这里放你自己的笔记和对原书的注解，只有你能看到」，并提供「新建笔记」与「去读书」两个入口。
- 讨论区 0 条评论：区分「还没有人评论，来写第一条」与「该内容不接受新评论」（已收回 / root 已删除）两种空态。
- PARTIAL 至少定义两处：发布时部分图片上传失败、备份时部分对象上传失败，显示「已完成 8/12，其余可重试」而非笼统失败。
- EMPTY 必须同时回答「为什么为空」和「下一步可以做什么」；仅一个图标或「暂无数据」不通过验收。

### 6.5 注解位置待确认

- 创建时歧义：选中文本在当前版本有多处匹配时，创建前在候选位置列表（带上下文片段）中确认，不得静默取首个命中。
- 迁移后歧义：「我的注解」提供「需要确认位置（N）」筛选入口，原书阅读页顶部同时提示。
- 待确认状态下注解正文始终完整可读可编辑，界面提示「注解内容已保留，仅原文位置需要重新确认」。
- 处置动作至少两个：「指认新位置」与「保留为无位置注解」（降级为独立笔记并保留原引文文本）。
- 已公开的注解进入待确认时，他人看到原引文文本与注解正文，不显示可点击的原书定位，也不显示内部状态词。

### 6.6 账号切换与分享管理

- 切换账号前若存在 dirty 或 save_failed 内容，弹出「《标题》有未保存的修改，保存失败。切换账号后可能丢失」+「重试保存 / 仍然切换 / 取消」；切换后重新登录原账号须能看到该内容或明确的丢失提示。
- 「我的」提供分享链接管理：列出本人创建的分享、可撤销；对方打开已撤销或内容已失效的链接时，使用 §6.2 的统一失效文案。
- 举报提交后给出受理确认，并在举报者本人视图中折叠该内容，避免重复举报。
