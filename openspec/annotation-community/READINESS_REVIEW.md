## 3. 三个角色的重点结论

### 用户体验

可开始工作包准备。编码前，相关 UI 工作包还要补以下局部交互附件，建议命名 `UX.md`，作为 README 的输入，不新增另一套需求真源。

- **页面 × 七状态矩阵**：每个状态写显示内容、主动作、保留数据、重试结果和 BDD 编号，不适用须说明。覆盖历史、列表、详情、讨论、@ 候选、通知、待处理、备份、回收站；分别由 NC-007/010/011/012/014/018/019 承接。依据 PRD §6.4、TASKS NC-010。
- **入口与返回表**：编辑→历史→返回、通知→楼内评论、账号切换、目标失权等，写目标参数、返回位置、草稿和滚动保留。NC-001 固定宿主入口；NC-007/010/014/022/023 实现各自局部规则。
- **低保真关键页**：NC-005/007/010 至少提供软键盘打开的编辑器、冲突对照/合并、发布预览，解释 320pt 与 200% 字体下布局、主次动作、滚动与焦点。依据 PRD §4.1/旅程 3、6。无需先做全套精美视觉稿。
- **恢复与来源依赖**：NC-018 的恢复材料页面等 NC-015 固定产品形态；NC-022/023 等 NC-020b 的真实锚点类型及样例。可先写页面状态骨架，不用静态假数据代替真实准入证据。

### 产品与阶段顺序

功能方向与范围可以保持。准备时须把现有计划中的局部分支落成唯一可执行安排：

1. NC-004 的本地优先路径已有授权选项：先冻结与加密无关的 outbox 外层契约，密文内容留 NC-016；否则等待 NC-015。必须在工作包中选择并记录，不能让执行者二选一（TASKS §1.1、NC-004）。
2. PLANS §6 说纯文本发布不受 E-BLOB 影响，但整项 NC-009 依赖 NC-008→NC-025。若提前做纯文本，须明确拆出的子范围及未完成的整项门禁；本轮不擅自解锁 NC-009。
3. NC-007 的完整合并旅程承诺 Undo/Redo，而总表只列 NC-004/005。其工作包必须登记 NC-006 相关能力的实际依赖或安排该子验收在 NC-006 后，不能提前宣称完整历史旅程通过（TASKS NC-007）。

这些是执行包准备的收敛项，不推翻 v1.4 产品验收。

以 [工作包准出规范](../subagent-delivery-gate.md) 为权威；不因采用 OpenSpec 再复制一套 proposal/design/tasks。已有总规格继续引用，新增任务级工件进入既有目录。

| ACCEPTANCE.md | 独立复跑步骤、正常/负向证据、差异范围、既有失败区分；不接受空断言或仅 Fake 路径通过 |
| PROMPT.md | 上述工作包定位、允许/禁止范围、验证和提交要求、交付证据格式；通过 ACT 审查后才交付执行者 |
