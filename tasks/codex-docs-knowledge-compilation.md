## 决定记录

**2026-08-22 根因（两条，独立）**

**根因1：硬编码绝对二值化阈值**
- 位置：`ocr/src/gujiorc/ocr/segment.py::segment_block` 的 `dark = region < 128`
  （`symbol_gap_repair` 同样硬编码 128）
- 机制：古籍扫描的背面透印字/浅印字灰度在 176~229 区间，区域内不存在任何
  像素 < 128 → 投影密度全 0 → `_find_gaps` 返回空 → `segment_block` 返回 `[]`
  → `segment_page_chars` 里 `if not seg_boxes: continue` 静默跳过整行。
- 实测：139 个零段行的区域最暗像素 **100%** ≥128，吞掉 493 字。
- 引入于：M2 单字切分初版（该阈值自始为常量，非回归）。

**根因2：投影段与行文本按位置配字**
- 位置：`segment_page_chars` 的 `char = text_chars[si] if si < len(text_chars)`
- 机制：PaddleOCR 输出的是**整行文本**，段边界由 Y 投影独立算出，两者数量无
  任何约束关系。「一」「二」「三」等横笔画字、「宫」「主」等内部有横向空隙的字
  会被切成多段（实测「一二三」→6 段），于是从该字起整列后移：前字被后字顶掉、
  末尾若干框拿不到字。交接文档里的「字错位」「琅玕重叠」「八一合框」是同一根因
  的三种表现，不是三个 bug。
- 实测段数−字数分布：+1 有 134 行、+2 有 44 行；−1 有 47 行、−5 有 24 行。

**取舍：为什么不走「逐字重识别」**
每个单字框裁图后再调 rec 模型，可彻底摆脱位置配字。但 `ocr/docs/HANDOFF.md`
§9 记载 PaddleOCR 3.7.0 切到 `predict` 接口后在曲线实验中卡住，风险未清；
且 3000+ 次 rec 调用成本高。故先做确定性的「段数向字数强制对齐」（无模型依赖、
可测、可复现），逐字重识别留作后续可选增强。

**顺带发现（不在本次范围，另立任务）**
- `tests/test_segment.py` 的既有断言是围着 bug 写的：`assert len(segs) >= 2`、
  `assert n >= 2`，且合成图时 `if ch == "得": continue` 只画 2 字却传 3 字文本。
  这类宽松断言是缺陷长期未被发现的原因。本次不改它（范围锁死），仅新增
  `test_segment_alignment.py` 作为契约测试。

## 踩坑墓地

**别重试：`_merge_thin_segments` 调 `min_h_floor` 治不了切过头**
前任把 `min_h_floor` 设为 4.0 想合并细段。实测「一二三」的 6 段高度为
[4,3,3,3,3,4]，中位数 3，判据 `h < median*0.45 and h < 4.0` 即 `h < 1.35`，
**一段都合并不掉**。细段高度与中位数同量级时该判据必然失效——因为中位数本身
已被细段污染。方向错在「用段高中位数当典型字高」，横笔画字整列都是细段。

**别重试：`line_box["h"] > 45` 时降 `min_gap` 再切**
前任为 page_005「八一」加的 special case。降 min_gap 只会切出**更多**段，
在段数已经多于字数的主流失配方向上是反向加压。实测 +1/+2 段占 178 行，
远多于 −1 段的 47 行。

**别重试：过滤 `w<8 && h<8` 空框治假「口」字**
交接文档已记「阈值需更仔细调节」。实测按「单字 line 且框 w<12 或 h<12」筛，
全10页命中 **0 个**——假「口」字的框并不小，靠尺寸阈值抓不到。
