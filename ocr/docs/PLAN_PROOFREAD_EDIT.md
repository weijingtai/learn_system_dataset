## 0. 需求原文（不得改写）

> 增加一些功能，
> 1. 可以 CRUD/撤销(Command+Z) 识别框以及其中的内容，能够保存编辑；
> 2. 编辑之前可以用鼠标框选多个。
> 3. 识别框，无论是蓝色还是黄色的，可以被合并，这个是为了处理，当一个文字被分成了两个字，比如说「二」被当做了 2 个「一」；
> 4. 可以把一个框从另外一个框拆出来，譬如说「八二」被识别成了「八一」和「一」；
> 5. 设计一个实现的功能，当前的 page_01 中有一个问题特别具有代表性，这个功能你看一下要怎么做？「三辰通载」被识别成了 `[二(三)][一(辰)][辰(通)][通载(载)]`，`[]` 这里为识别框选的蓝框，`()` 这里为识别结果。因为空识别出来了一个字「一」，导致后面的字会使用下一个字的识别结果，最后的结果就是这一行的最后几个字被框选成为了一个。

第 1~4 点是实现请求；**第 5 点是设计问题**（「你看一下要怎么做？」），§1 是对它的正式回答。

## 1. 第 5 点的诊断：这是一类缺陷，不是一个 bug

### 1.1 用户记号的含义

`[框内实际字形(该框被赋予的识别结果)]`。所以用户说的是：第 1 个蓝框里实际只有「三」的上两横（看起来像「二」），却被赋了「三」；第 2 个框里只有「三」的第三横（看起来像「一」），却被赋了「辰」；……最后一个框里实际装着「通」和「載」两个字，只被赋了「載」一个字。

### 1.2 与真实数据核对（`page_001.json`，已逐字核对通过）

| 框 id | box (x,y,w,h) | 现有 `char` | 框内实际字形 |
|---|---|---|---|
| `page_001c0000` | 1061, 263, 88, **24** | 三 | 「三」的上两横 |
| `page_001c0001` | 1061, 298, 88, **9** | 辰 | 「三」的第三横 |
| `page_001c0002` | 1061, 328, 88, 58 | 通 | 辰 |
| `page_001c0003` | 1061, 399, 88, **131** | 載 | 通 + 載 |

行框 `page_001L0` = (1061, 250, 88, 288)，行文本 `三辰通載`，`conf=1.00`。

**关键事实：行文本本身是完全正确的。** 错的只有段边界（几何）。

### 1.3 机制：两个错误互相抵消，逃过了既有契约

PaddleOCR 给的是**整行文本**；单字框是沿 Y 轴墨迹投影**另算**的。二者之间没有任何数量约束，切分层只有一条事后契约：**段数 == 字数**。

这一列同时发生了两个方向相反的错误：

- 「三」的三横之间留白够大 → 被切成 **2 段**（多了 1 段）
- 「通」「載」之间留白不足 → 被并成 **1 段**（少了 1 段）

净效果 0。段数 4 == 字数 4，契约**满足**，测试**不报警**。但从第 2 个框起，每个框都装着下一个字的识别结果——这正是用户说的「后面的字会使用下一个字的识别结果」。

> 结论：`段数==字数` 是必要条件，不是充分条件。这类缺陷必须靠**几何**判据发现，不能靠计数。

### 1.4 为什么「逐框改字」是错的解法

有人会想：直接把 c0001 改成「三」、c0002 改成「辰」……不行，两个原因：

1. **框还是错的。** c0000/c0001 各装半个字，任何下游（导出图片、重识别、字形归组、Zvec 向量化）拿到的都是残缺字形。
2. **工作量与错误率。** 全书这类行 41 处，每处平均 4~20 个框要手改，且一旦数错一位，整行连环错。

有测试把这一点钉死（`test_reflow_alone_cannot_fix_misalignment_geometry_must_come_first`）：单独对这一列执行「重灌」，结果与修复前**逐字节相同**——因为框数已经是 4、文本也是 4 字，重灌只是把原样的错误顺序又灌了一遍。**必须先修几何。**

### 1.5 答案：三步修复法 + 自动诊断

**修复动作（三步，缺一不可）：**

| 步 | 操作 | 对这一列的具体动作 | 效果 |
|---|---|---|---|
| ① | **合并** | c0000 + c0001 → 一个框 (y=263, h=44) | 段数 4 → 3 |
| ② | **拆分** | c0003 等分 2 份 → (y=399,h=66) + (y=465,h=66) | 段数 3 → 4，且**每个框各含一个完整字** |
| ③ | **重灌** | 把行文本 `三辰通載` 按阅读序重新分配到这 4 个框 | 框↔字重新对齐 |

真实 `page_001.json` 上已验证：③ 之后 三/辰/通/載 各归其位，`orig_char` 全部保留，诊断不再报警。

**为什么第 ③ 步是「重灌」而不是「改字」：** 错位是**整体位移**，不是逐字随机错。位移的正解是把正确的行文本按修好的几何重新分配一次，一个动作修完整行。

**自动诊断（配套，否则人要肉眼数几百个框）：** `diagnose_page()` 把行长按字数等分成「字位」（`pitch = 行长 / 字数`），逐框算三个几何信号：

| 信号 | 判据 | 含义 |
|---|---|---|
| `over` | 框长 > 1.6 × pitch | 一个框跨了多个字位（如「通載」并成一框）→ 该**拆分** |
| `thin` | 框长 < 0.25 × pitch | 一个框只装一条笔画（如「三」的单横）→ 该**合并** |
| `drift` | 框心偏离应在字位 > 0.6 pitch | **从这里起文字被整体移位**——真正抓错位的信号 |

判定规则：必须有 `over` 或 `drift` 才报警。**`thin` 单独出现不报**——「一」「二」这类字本身就矮，那是正常的。

每个框还输出 `expect_char`（按几何该装的字）。这一列的取值必须来自**框实际落在第几个字位**，而不是 `text[i]`：切分层本来就是按位置配字的，用 `text[i]` 等于拿错误答案当标准答案，那一列永远显示「正确」，等于没诊断。（`test_diagnose_expect_char_comes_from_geometry_not_position` 钉死此点。）

|---|---|
| page_001 | **4 / 4** |
| page_003 | 2 |

## 2. 数据铁律（每个操作都必须守）

| 铁律 | 在本功能中的落实 |
|---|---|
| `orig_char` 永不覆盖 | 所有改字走 `CharBox.set_char()`，只写 `char` + `mapping` |
| 不得伪造字符 | `split` 不给字时，各段如实标 `unrecognized`，**绝不把源框的字复制给每一段**；`reflow` 框数≠字数时**拒绝执行** |
| 不静默丢弃 | `merge`/`split` 会删源框，因此把源框**完整快照**写进新框 `extra.edit.orig_snapshot`；`delete` 把被删框快照写审计日志 |
| 改动可追溯 | 每个操作写 `logs/audit.jsonl`（append-only） |

`models.py` 的小改：`set_char()` 原来只在 `mapping_source == "manual"` 时标 `corrected`，改为 `startswith("manual")`——因为本功能引入了 `manual:merge` / `manual:reflow` 等细分来源，它们同样是人工改正。已确认不影响 `opencc_simp` / `glyph_group`。

`audit.py` 的小改：`ACTIONS` 增加 `merge / split / delete / update / reflow / undo / redo`。

## 3. 后端（已完成，全绿）

### 3.1 `core/edit.py` — 七操作 + 一诊断，全部纯函数（只吃 `PageResult`，不碰 HTTP）

| 函数 | 签名要点 | 对应需求 |
|---|---|---|
| `merge_boxes(pr, ids, char=None)` | 几何取并集；不给 `char` 则新字为各源框字的**拼接**（不猜、不重识别）；新框插在**首个源框原来的下标**（否则整页阅读序错乱） | 第 3 点 |
| `split_box(pr, cid, *, at=None, n=0, chars=None)` | 切向由框自身长宽决定（`h>=w` 按 y 切，否则按 x 切）；`at` 给绝对切线坐标（可多条），`n` 给等分份数，二者择一 | 第 4 点 |
| `delete_boxes(pr, ids)` | 返回被删框完整快照供调用方写日志 | 第 1 点 |
| `update_box(pr, cid, *, box=None, char=None)` | 改几何和/或改字 | 第 1 点 |
| `create_box(pr, box, char="")` | 按阅读序落位（竖排：同列内 y 递增处插入） | 第 1 点 |
| `reflow(pr, ids, text=None)` | **框数必须恰好等于字数，否则拒绝**；`text=None` 时取所属行的识别文本 | 第 5 点 |
| `undo(pr)` / `redo(pr)` / `push_history(pr)` / `history_depth(page)` | 整页 `chars` 快照栈，**落盘**到 `logs/edit_history/{page}.json`，上限 50 格 | 第 1 点 |
| `diagnose_page(pr)` | 返回疑似错位行列表，只报告不改数据 | 第 5 点 |

### 3.2 四个必须保留的实现约束（每条都是踩坑换来的）

1. **id 水位线必须在删框之前抬。** 页级单调水位 `pr.extra["next_seq"]`。`delete_boxes` / `merge_boxes` / `split_box` 的**第一行**都要调 `_seed_seq(pr)`：删掉尾框**之后**再算水位就看不到它了，新建框会重新发出刚删掉的号，撤销把旧框恢复回来即出现重号。撤销快照**只存 `chars`**，不含 `extra`，所以水位线不会被撤销拨回去。

2. **`reflow` 的诚实闸门不许放宽。** 框数 ≠ 字数一律拒绝，报错信息自带下一步（「请先用合并/拆分把几何修到框数=字数，再重灌」）。多一个框会凭空造字，少一个框会悄悄丢字，两者都违反铁律。HTTP 层把这条消息**原文**透传给前端。

3. **`_line_of` 用「框心落在行内」投票，不用严格包含。** 严格包含时，一个稍微出界的框（比如用户多选进来一个补标框）会让 reflow 报「找不到所属行」，把真正该报的「框数≠字数」挡在后面——用户看到的是无从下手的错误。

4. **`push_history` 必须清空 redo。** 撤销后又做了别的编辑，原来的重做目标已不在这条历史线上，重放会得到一个从未存在过的状态。

### 3.3 HTTP 契约（`local/app.py`）

统一约定，前端只需处理**一种**返回：

1. 改动前先 `push_history`（Cmd+Z 才有东西可回）
2. 改完立刻 `save_page_json`——**编辑即保存，不存在「未保存」状态**
3. 返回**整页 `chars`** + 撤销栈深度，前端整体替换即可，不必自己算增量
4. 改完重算 `detect_rare_chars`，否则新框在前端永远不着色
5. 写审计日志

| 端点 | 请求体 | 返回补充字段 |
|---|---|---|
| `POST /api/page/{page}/edit/merge` | `{ids:[...], char?}` | `id`（新框） |
| `POST /api/page/{page}/edit/split` | `{id, at?:[...], n?, chars?}` | `ids`（各段） |
| `POST /api/page/{page}/edit/delete` | `{ids:[...]}` | — |
| `POST /api/page/{page}/edit/update` | `{id, box?, char?}` | — |
| `POST /api/page/{page}/edit/create` | `{box:{x,y,w,h}, char?}` | `id` |
| `POST /api/page/{page}/edit/reflow` | `{ids:[...], text?}` | `text`（重灌后整串） |
| `POST /api/page/{page}/edit/undo` \| `redo` | 无 | — |
| `GET /api/page/{page}/edit/history` | — | `{undo, redo}` |
| `GET /api/page/{page}/misaligned` | — | `{items, count}` |

所有编辑端点公共返回：`{ok, chars:[...整页...], history:{undo, redo}}`。

错误码约定：`ValueError` → **400**（消息原文透传，它自带下一步该怎么做）；`KeyError`（框/页不存在）→ **404**；`IndexError`（撤销栈空）→ **409**。

## 4. 前端实现计划（`local/static/index.html`，待做）

现状：349 行 Vue3 + Element Plus 单文件。**只支持单选**（`selId`），两次点击补标框，`doFix` 单字改字。以下是改造方案。

### 4.1 状态模型

| 现有 | 改为 | 说明 |
|---|---|---|
| `selId: null` | `selIds: []` + `primaryId: null` | `selIds` 是唯一真源；`primaryId` 供右侧旋转/裁切预览用（单框才有意义） |
| — | `hist: {undo:0, redo:0}` | 工具栏显示可撤销层数 |
| `drawMode: false` | `mode: 'select' \| 'create' \| 'split'` | 三态互斥，用 radio-group |
| — | `drag: null` | 框选/拉框的过程状态（源坐标） |
| — | `cutAt: null` | 拆分模式下的切线位置（源坐标） |
| — | `misaligned: []` / `curIssue: null` | 诊断结果与当前查看的行 |
| — | `savedAt: ''` | 「✓ 已保存 HH:MM:SS」指示 |

坐标换算：现有 `S(px)` 是源→显示（`px * scale`）；新增 `toSrc(px) = px / scale` 和 `pt(ev)`（鼠标事件 → 源坐标）。

> ⚠ 现有 `onCanvasClick` 把**显示坐标**当源坐标 POST 给 `segment-new`，`scale != 1` 时补标框位置是错的。新实现一律先过 `pt()`，顺手修掉这个既有 bug。

### 4.2 鼠标交互（第 2 点）

- `#stage` 上 `mousedown` 开始拖拽，`window` 上监听 `mousemove`/`mouseup`（鼠标移出画布也不丢事件）。
- **select 模式**：拖出橙色虚线橡皮筋 → `mouseup` 时选中所有与该矩形**相交**的框（相交而非包含：竖排框细长，要求完全包含会很难框中）。按住 Cmd/Ctrl/Shift 为**追加**选择。未拖动（位移 < 3px）且未按修饰键 = 点空白清空选择。
- **create 模式**：拖一次即建框（`w>4 && h>4` 才提交），提交后自动回 select 模式。
- 框自身 `@mousedown.stop` 处理点选：Cmd/Ctrl = 切换该框；Shift = 从上一个选中到当前的**范围选**（按页内阅读序下标取区间）；无修饰键 = 单选。
- **split 模式**：给 `#stage` 加 class 让 `.box { pointer-events: none }`，所有事件落到 stage 上；`mousemove` 在选中框内时更新 `cutAt`，画一条红色切线（竖排框画横线）；`click` 提交 `{id, at:[cutAt]}`。同时提供「等分 2 份」按钮走 `{id, n:2}`（跨两字位是最常见情形，一键更快）。

### 4.3 键盘（第 1 点）

`document` 上监听，**开头即判**：焦点在 `INPUT`/`TEXTAREA`/`contenteditable` 时直接 return（否则在输入框里打字会触发快捷键）。

| 键 | 动作 |
|---|---|
| `Cmd/Ctrl+Z` | 撤销（`preventDefault`，否则浏览器自带撤销会插手） |
| `Cmd/Ctrl+Shift+Z` | 重做 |
| `M` | 合并选中框 |
| `S` | 切换拆分模式（要求恰好选中 1 个框，否则提示并留在 select） |
| `N` | 切换补标模式 |
| `R` | 按行文本重灌选中框 |
| `Delete` / `Backspace` | 删除选中框 |
| `Esc` | 回 select 模式并清空选择 |

### 4.4 编辑动作 → 接口映射

统一走一个 `post(op, body)`：调接口 → `applyChars(resp)` → 失败走 `fail(e)`。

`applyChars(resp)`：整体替换 `chars`；更新 `hist`；`savedAt` 打时间戳；把已不存在的 id 从 `selIds` 剔除；重建 `stats`/`rareList`/`columns`；重新拉 `misaligned`。

`fail(e)`：把响应体里的 `detail` **原文**弹给用户（`duration: 6000, showClose: true`），**不许压成「操作失败」**——reflow 的闸门消息自带下一步该怎么做，压掉了用户就无从下手。现有 `api()` 里 `t.slice(0,120)` 要放宽到 400，否则中文消息会被截断。

改字的两种语义（同一个输入框）：

- 选中 **1 个框** → `edit/update {id, char}`
- 选中 **N 个框**且输入 **恰好 N 个字** → `edit/reflow {ids, text}`（按阅读序重灌）
- 数量不符 → 前端直接提示「选了 N 个框，却给了 M 个字」，不发请求

### 4.5 诊断面板（第 5 点）

侧栏新增一节「疑似错位行 (N)」：

- 列出 `misaligned.items`，每行显示行文本 + 报警种类徽标。点击 → 选中该行全部框 + 画布滚动定位 + 下方展开逐框表格。
- 逐框表格列：`现字` / `应为`(`expect_char`) / `落位`(slot) / `序`(index) / `偏移`(drift) / `跨字位`(spans)。`shifted` 为真的行标红。

## 6. 决定记录

| 日期 | 决定 | 理由 |
|---|---|---|
| 2026-08-23 | 第 5 点用「合并→拆分→重灌」三步，而非逐框改字或自动修复 | 错的是几何不是文字；逐框改字留下残缺字形且易连环错。全自动修复需要判断「哪两个框该并」，那是字形判断，不该由几何阈值替人决定——**工具给诊断和动作，判断留给人** |
| 2026-08-23 | `reflow` 框数≠字数时**拒绝**而非尽力而为 | 多框会凭空造字、少框会悄悄丢字，都违反数据铁律。拒绝 + 可执行的错误消息比「部分成功」安全 |
| 2026-08-23 | 撤销栈**服务端落盘**，不放前端内存 | 刷新页面/切页/重启服务后仍能撤销；且与「编辑即保存」一致——磁盘是唯一真源 |
| 2026-08-23 | 撤销快照只存 `chars`，不含 `extra` | 让 id 水位线 `extra.next_seq` 不被撤销拨回去，避免恢复的旧框与新建框重号 |
| 2026-08-23 | 每个编辑接口返回**整页 chars** | 前端不必算增量，一处 `applyChars` 收口；merge/split 会改变列表长度和顺序，增量逻辑得不偿失 |
| 2026-08-23 | `diagnose_page` 的 `thin` 单独出现不报警 | 「一」「二」这类字本身就矮，单看 `thin` 会淹没在误报里；必须配 `over` 或 `drift` |

## 7. 已知限制 / 明确不做

- **不做自动批量修复。** 诊断能定位 41 行，但「哪两个框该合并」需要看字形判断。工具只提供诊断 + 三个动作 + 一键重灌。
- **`diagnose_page` 只覆盖「框数==字数」的行。** 框数≠字数是另一类问题（由切分层的 `段数==字数` 契约保证不发生），在此不重复报警。
- **诊断是启发式的。** 三个阈值（1.6 / 0.25 / 0.6）在 10 页实测下不误报干净行，但换书体/字号可能要调；阈值集中在 `core/edit.py` 模块顶部常量，便于调整。
- **不改切分层。** 本轮只做人工校对工具。让投影切分自己少犯这类错（如引入连通域约束）是另一件事，另立任务。
- **旧端点 `/api/page/{page}/fix` 与 `/segment-new` 保留**（CLI/兼容），但前端一律改走 `edit/*`——只有后者会压撤销栈。

### 8.2 途中挖出的数据铁律漏洞（已修）

`CharBox.from_dict` 的向后兼容兜底原本写成：

```python
if not d.get("orig_char") and d.get("char"):     # ← 错
    d["orig_char"] = d["char"]
```

它分不清两种情况：**旧数据根本没有这个键**（该兜底），和**键存在但值是空字符串**（不该兜底——那是 `split` 拆出来、OCR 确实什么都没认出来的框）。后果：拆出的空框一经 `reflow`/改字填上，存盘再读就变成「OCR 原本就认得这个字」，人填的字冒充机器识别，审计链断裂。

改判「键是否存在」（`to_dict()` 走 `asdict`，新数据必带此键，所以空串一定是故意的）：

```python
if "orig_char" not in d and d.get("char"):
    d["orig_char"] = d["char"]
```

新增 3 个测试钉死：内存态、存盘往返、真旧数据兼容各一条。

> 这个坑是**新功能才让它可达**的：在此之前流水线不会产出「orig_char 空而 char 非空」的框。老代码不等于安全代码。

### 8.2.1 途中修掉的撤销栈瑕疵：被拒请求不留「空撤销」（已修）

原实现所有编辑端点都是「先 `push_history` 再执行操作」，操作被闸门拒绝时（如 reflow 框数≠字数）
撤销栈里会多一格**与当前状态相同**的快照——用户按一次 Cmd+Z 毫无反应，再按才真正回退，
撤销像坏了。实测复现：三步修复 + 一次被拒的 reflow 后 `undo=4`（应为 3），三次撤销回不到原状。

修法：把「抓快照」与「落栈」拆成两步（`edit.snapshot_chars` + `edit.push_snapshot`），
HTTP 层改为**操作成功后才落栈**，被拒的请求快照直接丢弃。`push_history` 保留为两者组合（兼容）。
新增 `test_rejected_request_leaves_no_undo_entry` 钉死。HTTP 验收 19/19 全过（含
「三次撤销=原状（字段级）」「被拒请求 undo=3」「重做/撤销栈往返」）。
