## 2. 与任务书的一处出入：诚实闸门

任务书假定版面是圆的。实现里加了一道闸门：第 1 步算出圆拟合的**相对残差**
（半径 std / 半径均值），超过 10% 即判定「字不在圆弧上」，此时不假装第 2/3 步成立，
而是明确报告假设不成立、把角度假设退化为固定集 {0°,90°,180°,270°}（覆盖旋转的夹注），
阅读序退回按列排，继续跑第 4/5 步。这样无论版面是不是圆的都能得到一张可判断的对比表。

加这道闸门的理由，见下节实测：page_010 的残差是 37.1%。

## 3. 第 1 步实测：圆弧假设在 page_010 上不成立

| 检查 | 结果 |
|---|---|
| HoughCircles 候选圆数 | **362 个** |
| 字框中心最小二乘圆拟合 | 圆心=(470,886)，平均半径=416 |
| 半径相对残差 | **37.1%**（真圆弧排字应 <10%） |

362 个候选圆是密排文字造成的噪声投票——真星盘只有几个同心环。
37.1% 的残差说明字心散布在 ±37% 的半径范围里，是**矩形列阵**而非圆弧。

**page_010 根本不是圆形星盘**，而是密排的分野/廟格表：大字配多级小字夹注、
双行夹注、印章、页码。圆拟合类算法的前提在这一页不存在。

## 4. 第 4/5 步实测：置信度说「提升」，正确率说「毁掉」

第 4/5 步（逐字裁图 → 多角度旋转 → rec 重识别 → 按 conf 择优）与圆无关，
所以仍然完整跑了。表面指标很好看：

| 指标 | 值 |
|---|---|
| 原（行级）识别均 conf | 0.678 |
| 0° 单字重识别均 conf | 0.562 |
| **择优后均 conf** | **0.872**（看着提升 29%）|
| 择优后 conf 高于原值 | 271 / 356 (76.1%) |
| 最优来自旋转假设 | 245 / 356 (68.8%) |

但两个校验指标揭穿了这个假象：

### 校验1：单字框吐出多个字 = 明确的垃圾输出

| | 数量 |
|---|---|
| 0° 重识别 | 66 / 356 (18.5%) |
| **择优后** | **82 / 356 (23.0%)** |

而且这些垃圾的置信度极高：

```
房 → 永興軍路 (1.00)      海 → 湖南 (1.00)      四 → 三河 (1.00)
市 → 南路   (1.00)      青 → 鳳路 (0.99)      电 → 都府 (0.99)
```

`永興軍路`、`湖南`、`南路` 都是**真实存在的宋代行政区划名**。也就是说 rec 模型在
一个被旋转过的单字上，用它的语言先验**幻觉出了一串上下文合理的历史地名，
并给了满置信度**。对古籍语料来说这是最坏的失败模式：伪造的文本看起来合理、
且能通过任何置信度过滤。项目铁律明令「不得伪造字符」。

### 校验2：代理真值对照——把本来对的字改坏了

原识别 conf≥0.95 的字极可能本来就是对的（在正常竖排页 page_005 上实测，
单字重识别与这批字的一致率是 96.7%）。拿这 106 个字当参照：

| | 保住 | 改坏 |
|---|---|---|
| 0° 重识别 | 66 / 106 (62.3%) | 40 |
| **择优后** | **78 / 106 (73.6%)** | **28** |

被改坏的实例（页眉「三辰通載卷第一」原本 conf 全为 1.00）：

```
三(1.00) → 1     (0.66, 270°)      載(1.00) → 辰      (0.98,  90°)
辰(1.00) → 11    (0.92, 270°)      卷(1.00) → 通載卷   (0.99,  90°)
通(1.00) → 1     (0.73, 180°)      一(1.00) → 1      (0.93,  90°)
西(1.00) → J     (0.67,  90°)      東(0.99) → 小東西   (0.90, 180°)
```

七个字的页眉里**只有「第」活了下来**。标注图 `/tmp/p010_curve.png`：绿框=与原一致，
橙框=内容被改，全页 232/356 (65.2%) 是橙的。

### 为什么按置信度择优注定不成立

两条结构性原因，不是调参能解决的：

1. **汉字旋转后往往长得像另一个合法的字**（`三`转 90° 像 `川`、`一` 像 `丨`/`1`），
   模型对「另一个字」给出的高置信度是**正确的自信、错误的答案**。
2. **rec 是文本行识别器，不是单字分类器**，它带语言模型。喂进一个方向错乱的字，
   它会输出一串它认为通顺的字（`房→永興軍路`），置信度反而更高。

结论：**在这个 rec 模型上，置信度不可作为旋转假设之间的择优判据。**
要做旋转择优，必须有一个与语言先验无关的判据（如笔画方向直方图、
字形先验、或专门训练的单字方向分类器）。任务书 D.3 第 5 步的设计在这一点上是错的。

## 5. page_010 真正的问题是什么（不是旋转）

顺手量到的，与旋转无关：

| 指标 | page_005（正常） | page_008（正常） | **page_010** |
|---|---|---|---|
| 字框高中位 | 22px | 23px | 22px |
| 字框高 p10 / p90 | 15 / 27 | 17 / 28 | **10 / 44** |
| 高 <12px 的字占比 | 3.9% | 2.5% | **14.0%** |
| 框高 > 2× 中位的字 | 0 (0.0%) | — | **34 (9.6%)** |

三个真实成因：

1. **多级字号**：14% 的字不足 12px 高（正常页 3.9%），是多级小字夹注。
   行级识别在这些行上置信度只有 0.12~0.30，出来的文本本身就是垃圾。
2. **双行夹注被检测成互相重叠的行**：例如 `page_010c0087`(x=798,w=34) 与
   `page_010c0089`(x=825,w=31) 在 x 上重叠，两列半宽夹注的字框在同一空间里交错。
3. **低置信行的垃圾文本被摊到噪声投影段上**，产生畸形字框。页眉列
   `text='三辰通載卷第一'`（7 字，列高 214px，本应每字约 30px）实得
   三h4 / 辰h10 / 通h3 / 載h21 / **卷h92** / 第h37 / 一h6 —— `_align_to_count`
   保住了「框数=字数」，但纯按「最小间隙」合并在投影噪声大时会产生极不均匀的框。

## 6. 结论与建议

**不予接入生产管线。** 理由不是效果不够好，而是**净效果为负**：它会把本来识别对的
字改成高置信度的错字，且会幻觉出貌似合理的伪造文本，直接违反项目铁律。

真星盘图（字确实沿圆弧排布）上这套算法**仍未被验证过**——page_010 不是星盘，
首轮那张真星盘图已丢失。要验证需要：

1. 找一张真正的星盘/环形图并**入库**（首轮的教训：测试图没提交，结论无法复现）。
2. 把第 5 步的择优判据换掉，不能用 rec 置信度（见 §4 末）。
3. `synth_star_chart.py` 的 `put_char_rotated()` 目前是空壳（注释自承「只做占位」，
   字并没有旋转），要先把旋转真正实现，否则连合成图都验证不了旋转识别。

对 page_010 这类**密排多级夹注表**，正确的方向与旋转无关，按性价比排序：

1. **双行夹注列拆分**：在识别前把重叠的半宽列分开，各自单独识别。
2. **小字上采样后再识别**：<12px 的字直接送 rec 命中率很低，先放大。
3. **低置信行不要摊字**：行级 conf < 0.4 时，与其把垃圾文本摊到投影段上产生畸形框，
   不如整行标 `unrecognized` 交人工——这与已挂上的异常版面登记是同一条思路。

目前 page_010 已被 `assess_layout()` 判为 `irregular_layout` 并登记到
`logs/anomalies.jsonl`，垃圾识别不会静默进入语料。这是当前的止损位。

实验那份页数据严守数据铁律：`orig_char` 保留**生产管线的识别**永不覆盖，`char` 放
择优结果，改动写进 `mapping`（含旋转角与来源假设），`extra.curve_exp` 记下
0°/择优的字与置信度、环号、极角。所以 Web UI 的框标注直接显示
`实验结果 ≈ 原识别`（如 `荆州≈建`、`永興軍路≈房`、`三河≈四`），逐字可查可回退。

两边的对照读数：

| | 生产（8000） | 实验（8001） |
|---|---|---|
| 字框 / 有字 | 359 / 356 | 356 / 355 |
| 均置信度 | 0.678 | **0.874** |
| 生僻字标记 | 148 | **51** |
| 改动标记 (`corrected`) | 0 | **231** |

⚠ **这张表是本报告最需要警惕的地方**：置信度涨了、生僻字标记少了，两个数字都朝
「更好」的方向动，但 §4 已证明这是幻觉造成的假象——模型把认不出的字换成了它认得的
常用字和地名，所以「生僻」自然变少、置信自然变高。**不要用这两个指标判优劣。**
打开 8001 的竖排译文面板通读一遍就很清楚：读出来是一串貌似合理的宋代地名，
而不是这一页真正的内容。
