# NC-007 可观察行为（BDD）

所有断言基于 `flutter test`，时间由注入的 `Clock` 控制，仓储使用 `NoteRepository` 或 `FakeNoteRepository`。

| ID | Given | When | Then |
|---|---|---|---|
| B01 | 两段单行文本 `hello` 与 `hello world` | 调用差异计算 | 返回一个未变更块 `hello` 与一个新增块 ` world` |
| B02 | 包含删除与修改的多行文本 | 调用差异计算 | 返回带有正确行号范围的 `deleted` 与 `inserted` 块 |
| B03 | 包含 10 行连续未变更的文本 | 开启折叠计算 | 中间未变更行折叠为单个 `isCollapsed=true` 块，两端保留上下文行 |
| B04 | 包含折叠块的差异结果 | 调用展开指定折叠块 | 对应块标记为已展开，完整行可读 |
| B05 | 包含三处变更的差异结果 | 调用跳跃导航方法 | 依次准确定位到上一处与下一处变更块的列表索引 |
| B06 | 首行插入与末行删除的边缘情况 | 调用差异计算 | 行范围索引准确，不产生越界异常 |
| B07 | 1 MiB 大小的 Markdown 长文本 | 调用差异计算 | 单线程在限制时间内完成计算，无异常抛出 |
| B08 | 任意私人内容对比 | 检查网络与端口 | 零 HTTP 请求，零外部服务调用 |
| B09 | 笔记存在 3 个历史修订 | 渲染历史修订页面 | 列表按时间降序展示全部 3 个修订及其 ID、说明与设备标识 |
| B10 | 笔记存在 2 个 head 分支 | 渲染历史修订页面 | 列表准确标识出处于 head 状态的修订及首选版本 |
| B11 | 历史列表展开某修订项 | 点击查看快照详情 | 页面展示该修订保存时的完整标题、正文与引用项 |
| B12 | 选中某个历史旧修订 | 点击恢复此版本 | 调用 `restoreRevision` 生成新修订，新修订包含 `restoredFrom` 字段 |
| B13 | 恢复操作完成后 | 检查修订库全量列表 | 既有旧修订未被删除或修改，历史链条完整保留 |
| B14 | 历史记录中仅包含 1 个版本 | 渲染历史修订页面 | 页面正常呈现且无恢复按钮或仅展示当前版本标示 |
| B15 | 请求不存在的修订 ID | 调用仓储获取方法 | 抛出指定错误且页面呈现友好错误提示 |
| B16 | 笔记仅有 1 个 head | 检查冲突状态 | 控制器处于非冲突状态，无冲突警告 |
| B17 | 笔记具有 2 个或更多 headRevisionIds | 实例化冲突控制器 | 控制器处于冲突状态，标记为存在多设备分支待处理 |
| B18 | 处于冲突状态的笔记 | 用户选择保留本机 | 调用 `mergeHeads`，以本地快照为合并结果，冲突状态消除 |
| B19 | 处于冲突状态的笔记 | 用户选择采用对方 | 调用 `mergeHeads`，以对方快照为合并结果，正文更新且冲突状态消除 |
| B20 | 处于冲突状态的笔记 | 用户选择稍后处理 | 会话标记置为 dismissed，冲突横幅关闭，不阻断常规编辑 |
| B21 | 选稍后处理后继续编辑正文 | 触发 2000 ms 去抖保存 | 正文正常保存为本地首选 head 的新修订，横幅不再自动弹出 |
| B22 | 正在编辑手动合并稿时外部到达第三个 head | 冲突检测触发刷新 | 用户当前正在编辑的合并稿不被覆盖，保留现场并更新 heads 清单 |
| B23 | 执行任何冲突决策 | 检查仓储调用路径 | 全部经由 `NoteRepository` 公开接口，无越权直接写库行为 |
| B24 | 具有多个 head 的笔记进入编辑页 | 渲染编辑页面 | 顶部展示非阻断冲突横幅，正文默认呈现本机首选版本 |
| B25 | 冲突横幅展示时 | 用户直接在正文输入框打字 | 输入框响应键盘输入，光标正常移动，无模态弹窗拦截 |
| B26 | 点击冲突横幅「查看对照」按钮 | 触发导航 | 呈现分支对照视图，左右或上下分块显示两端快照及行级差异 |
| B27 | 对照视图中 | 检查操作选项按钮 | 明确展示「保留本机」「采用对方」「手动合并」「稍后处理」四个操作项 |
| B28 | 在对照视图点击「稍后处理」 | 退出对照页返回编辑页 | 横幅关闭，编辑态继续保持 |
| B29 | 在对照视图点击「保留本机」 | 确认操作 | 调用合并流程，退出对照页并呈现合并完成通知 |
| B30 | 在对照视图点击「采用对方」 | 确认操作 | 正文内容刷新为对方版本，退出对照页并呈现合并完成通知 |
| B31 | 在对照视图点击「手动合并」 | 进入手动合并工作区 | 呈现合并编辑框，预填合并草稿，支持 NC-006 撤销重做按键 |
| B32 | 在手动合并工作区编辑完成后点击保存 | 提交最终合并稿 | 调用 `mergeHeads` 持久化新修订，成功退出并更新编辑页正文 |
| B33 | 20 000 行文档，只改第 10 行与第 19 990 行 | 调用差异计算 | 变更块的 old+new 行数合计恰 4；耗时 < 2000 ms |
| B34 | 去掉公共前后缀后中间区 6 000 行，每 1 000 行改一处（6 处） | 调用差异计算 | 变更行数合计恰 12 |
| B35 | 3 000 行全 `x` 对 3 000 行全 `y`（无唯一公共行） | 调用差异计算 | 允许整体删插；耗时 < 2000 ms；按块顺序把 unchanged/deleted 文本拼回等于 old、unchanged/inserted 拼回等于 new，且各块 `oldStartLine/newStartLine` 连续 |
| B36 | 冲突态，打开手动合并工作区，仓储替身记录调用 | 在正文输入并推进 2 500 ms，再点击「保存合并」 | 推进期间 `saveSnapshot` 调用 0 次；点击后 `mergeHeads` 恰 1 次且 `headIds` 等于进入冲突时的全部 heads |
| B37 | 真实 Drift 库：创建笔记、保存一次、把旧修订插回 `note_heads` 形成两 head | `checkConflict` → `updateManualDraft` → `commitManualMerge` | 成功；`headIds` 恰为合并修订一个；其 `parentIds` 集合等于原两 head；旧修订全部保留 |
