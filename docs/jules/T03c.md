## 一、背景（为什么要做）

本仓库是一条古籍知识编译流水线，分 M1–M8 八个阶段，每个阶段是 `pipeline/` 下的一个 Python 包。
所有阶段都必须**只经 `LedgerPort` 端口**读写账本（Ledger），不许直接碰账本内部的 `.store` / `.objects`。
这样以后换存储实现时，各阶段不用跟着改。

检测器是 `pipeline/contract_registry/acceptance.py` 的 `scan_ledger_internals`：扫描包内全部 `*.py`（任意层级 `tests/` 目录除外），
正则 `\.store\b|\.objects\b` 命中即算走后门。

之前的任务 T03 已把 M3（`corpus_compiler`）、M5（`validation`）、M8（`dataset_compiler`）清零。
但下面 5 个包当时还没登记成生产模块，没被扫描，**至今仍有 111 处后门**（在 `215d1e3` 上实测）：

| 阶段 | 包 | 命中数 | 分布 |
|---|---|---|---|
| M1 | `pipeline/intake` | 3 | acceptance.py 2、step.py 1 |
| M2 | `pipeline/digitization` | 5 | acceptance.py 2、step.py 3 |
| M4 | `pipeline/knowledge_extraction` | 22 | acceptance.py 8、inputs.py 7、step.py 7 |
| M7 | `pipeline/assembly` | 28 | acceptance.py 18、incremental.py 2、inputs.py 5、step.py 3 |
| M6 | `pipeline/review` | 53 | acceptance.py 20、step.py 19、console.py 6、inputs.py 4、testing/upstream_stub.py 3、rework.py 1 |

它挡着下一个任务 T04（把 M1→M8 由调度器连成一条线）：这些包一登记成生产模块，契约检查 `modules_port_clean` 就从 PASS 退回 BLOCKED。

规则（与 T03 相同）：

1. 每一处命中改成经端口的等价调用。端口里有现成方法就直接用。
2. **端口缺查询时**，按 `fd0ba6e` 的做法给端口补一个**只读**方法：协议写在 `pipeline/contract_registry/ports.py`，
   实现依次落在 `pipeline/ledger/client.py`、`service.py`、`store.py`，**SQL 只许留在 ledger 层**；
   在 `pipeline/ledger/tests/` 里给每个新方法补用例。
3. **行为不许变**：返回值、排序、异常类型、错误文案都保持原样。改完后该包原有测试必须全绿。
4. 测试里用来模拟账本的假对象（fake）如果靠 `.store` / `.objects` 工作，改成只提供端口方法——这样以后谁再偷偷走后门，用例会立刻报错。
5. `acceptance.py` 和 `review/testing/upstream_stub.py` 也在扫描范围内，一样要清。

## 三、不许做的事

- **不许改检测器**：`scan_ledger_internals` 的正则、扫描范围、排除规则一字不动（改了等于放宽检查）。
- 不许为了躲过正则而改写法（例如 `getattr(x, "st" + "ore")`、改变量名绕开 `.store`）。注释里出现 `.store` 字样也会被计数，改措辞即可，但**不许用这种方式掩盖真实访问**。
- 不许改 `pipeline/contract_registry/registry.yaml`、`pipeline/orchestrator/`（属 T04）。
- 不许改任何写入语义；如果某处后门是**写**操作且端口没有对应写方法，**停手写待裁决**，不要自己加写方法。
- 不许删除或跳过任何既有用例；不许新增 skip。
- 不许推送或合并到 `main`；在你自己的分支上工作，完成后开 PR。
