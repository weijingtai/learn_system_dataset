所以「无 ORDER BY」的几处都实测为 rowid 写入顺序；`reviewed_candidate`/`review_queue` 两处特意用
`list_revisions`（`ORDER BY r.rowid`）而不是 `list_step_run_revisions`（`ORDER BY r.created_at, r.rowid`），
以免 `created_at` 与 rowid 不一致时顺序漂移（重复 `entity_id` 时是「后写者胜」）。
`list_frozen_inputs` 的次序（`artifact_revision_id` 升序）恰好等于原查询的索引扫描次序。
