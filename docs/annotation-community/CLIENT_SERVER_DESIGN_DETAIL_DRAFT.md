# 笔记与原句注解：客户端、服务端接入细化

状态：`DRAFT_FOR_USER_REVIEW`；2026-09-10。本文把已确认目标转成可审查的交互与接入规则；具体默认值仍为提案，不等于用户已批准，更不代表代码已接通。

关联：[主数据草案](SERVER_DATA_CONTRACT_DRAFT.md)、[私人存储草案](PRIVATE_NOTES_STORAGE_DRAFT.md)、[书籍资产交付](BOOK_ASSET_DELIVERY_CONTRACT_DRAFT.md)。书籍 U/A 回执仍由上游线处理，本轮不重新定义书籍 ID、选区单位或发布包格式。

实现依据为 [三路 Terra 调研及主 Agent 复核](MODULE_REUSE_AUDIT.md)。已确认目标、当前代码能力、下面的候选默认值是三个不同层面。旧模块只提供部分基础，新增接线不被归类为重复造轮子。

## 1. 本期交付边界

- Flutter：笔记列表、独立 Markdown 编辑/预览、历史与差异、发布/更新发布/收回、原句注解、公开详情及两级讨论、本人回收站与同步/备份状态。
- Tooltip：围绕真实目标的查询、详情、评论、回复、赞踩、收藏、分享、资料/私信入口和通知回跳原型；不向排盘子模块安装最终 Widget。
- Python：公开投影与业务命令、权限与并发、讨论互动、通知事件、资源访问、与既有存储同步的接线。私人正文由客户端加密后备份，不能借通用 REST CRUD 暴露明文。
- 下一版：原书/Markdown 分屏、Markdown 引文点击跳转、自由圈画。原句注解保存准确锚点和返回创建处是本期基础能力。
- 不新增推荐算法、富文本自有文档引擎、登录系统或密码协议。

## 2. 保存、历史与发布

| 用户动作 | 私人持久数据 | 公共结果 | UI 成功条件 |
|---|---|---|---|
| 输入 | 编辑缓冲，尚未保存 | 不变 | 显示未保存，不能显示云备份成功 |
| 自动/手动保存 | 有效内容变化产生不可变 revision，并原子更新本地 head | 不变 | Drift 事务成功后显示本地已保存 |
| 首次发布 | 先固定选定 revision | 服务端新建 publication 和公开指针 | 服务端确认后才显示已发布 |
| 已公开后编辑保存 | head 前进 | 仍显示旧 published revision | 显示有未发布修改 |
| 更新发布 | 固定新的选定 revision | 服务端切换公开指针，保留发布历史 | 服务端确认及本地回填成功 |
| 恢复历史 | 以旧内容生成新 revision，记录 restored_from | 不自动改变公开版本 | 新 revision 已保存 |
| 收回公开 | 保留私人修订与备份 | 禁止公共读取和新互动 | 服务端确认，不能只改本地开关 |

候选默认：输入停止 2 秒后保存；失焦/返回时尝试立即落盘，失败则保留编辑缓冲并提示重试。相同规范内容与附件/引用集合不重复建修订；未持久的击键不作为审计版本。已持久版本不覆盖，列表允许按编辑会话归组。比较内容在客户端完成，公共发布版本可在服务端比较。

并发：revision 可有多个 parent；同一 head 的多设备编辑不得用时间戳淘汰其中一版。第一版提供“保留当前/使用另一版/手动合并”，用户选择产生新修订并标记已解决分支，不删除原分支。服务端公开更新用 ETag 前置条件拒绝过期发布；不自动把本地最新 head 发出去。

账号切换前停止该账号同步任务，关闭私有库/密钥句柄；后台回调必须核对原账号 scope。账号会话过期仍可在已有授权本地会话策略允许时保存，不得以旧凭据继续发布或访问另一账号资源。具体解锁策略复用宿主。

## 3. 私人同步与备份交互

分别显示 `local_save_state`、每通道的 `sync_state`、`backup_state`；不合成单个“已同步”图标掩盖未备份。

建议首次启用说明备份内容和恢复条件，经用户选择后自动执行；关闭仅停止未来备份，删除云备份是单独命令。若宿主已有明确默认值则沿用并在入口展示，不引入相冲突的新全局开关。

在密钥恢复机制尚未得到真实实现证据前，不展示“换手机后一定能找回”的承诺。区分已配对设备迁移和全部设备丢失的恢复。可恢复备份必须覆盖清单、依赖修订、附件、必要密钥封装与协议版本；单个上传成功不能标记整份笔记可恢复。

## 4. 删除、收回与留痕

提案：收回公开、放入回收站、彻底删除是三个独立动作。

- 收回公开保留内容与讨论，只关闭公共访问；再次发布不生成第二套 thread，旧讨论仍保留其所见 publication。
- 放入回收站先保留历史，发出版本化 tombstone；若当前公开，则必须先由服务端关闭访问并返回确认，离线时显示待收回，不能声称他人已不可见。
- 候选默认回收站保留 30 天；恢复生成恢复事件，保持私密，不自动恢复公开。
- 彻底删除正文、附件和可识别引用时，需要同步删除传播与云备份清理。最小不含正文 tombstone 的保留窗口应覆盖允许离线设备的重入规则；超过窗口的设备必须全量对账，不能上传旧快照复活内容。
- 备份中已删除对象通过清单及可验证清理处理；共享附件须先检查其引用，不能删除其他笔记仍使用的对象。删除任务未完成时显示处理中。
- 他人评论的正文删除、账号删除和审核审计保留需分别定义。可先以主题不可访问墓碑保持讨论关系，不给公众提供被删除笔记的旧引用预览。

30 天及彻底删除的保留窗口为产品/存储策略候选，不能由现有软删字段推定已实现。修改留痕不表示私人正文永久无法删除。

## 5. Markdown 与媒体

本期基础提案：标题、Markdown 源文输入、常用格式插入、预览、撤销/重做、自动/手动保存、历史比较。渲染指定 `flutter_markdown_plus`，编辑能力与渲染能力独立选择；不以引入渲染器冒充已有编辑器。

建议本期支持插入图片，通用文件附件后置；若图片链路未达标，文本编辑可独立完成验收但不能声称图片已交付。工具栏不出现未接通操作。图片尺寸/数量/总量沿用媒体系统可配置限额，实际限制须在接口中明确，不先硬编码猜测。

私人图片使用内部 attachment ID，通过受控 resolver 从当前账号解密读取；Markdown 不写永久公共下载 URL、密钥或本机绝对路径。发布时为选定修订准备公开资产副本/投影；不可直接修改私人对象 ACL。资源就绪后才允许发布。

公共媒体若要求“收回立即拒绝新请求”，必须通过每次校验当前权限的访问入口；不能发出可脱离 ACL 重用的长期公开 URL。短期签名 URL 在到期前仍可访问，若选用这种分发方式就必须显式改成有限撤权窗口，不能两种承诺同时写入验收。本稿建议社区媒体采用当前 ACL 访问入口；书籍原件下载与私人密文备份票据属于不同资源策略。

外部图片提案：私密编辑与预览默认不自动请求外部地址，由用户显式加载；避免原始 URL 在私密预览时向外发送请求。发布不自动由服务器抓取任意 URL；若未来加入导入流程需采用既有媒体接入与请求限制。普通链接交由宿主安全链接打开机制处理，Markdown 原始 HTML 不执行。

@ 使用稳定账号 ID 与显示名快照的结构化记录；原始文本中的普通 @ 不自动当作有效通知收件人。客户端提供候选选择，服务端校验授权及被提及对象，私人草稿不发通知。

## 6. 两入口与讨论调用契约

原书和 Tooltip 均输入经过校验的 `DiscussionContext`（目标类型、稳定身份、所见修订、可选选区）；解析后返回统一 `thread_id` 和内容关联，而不是依据入口创建两份帖子。

`DiscussionView` 提案包含：上下文摘要、当前可读 publication、正文/引用、作者资料摘要、counts、viewer reaction/bookmark 状态、capabilities、一级评论页及楼内预览。`capabilities` 仅帮助 UI 展示，所有写操作仍由服务端重新鉴权。

一级评论独立分页，楼内回复独立分页；楼内任意回复仍为 depth=1，必须携带 root 与 reply_to，服务端检查其归属。删除评论显示墓碑，不能导致回复错挂其他楼。排序必须有稳定唯一 ID 作为最终排序键；界面阅读分页延后不意味着 API 可以返回无限评论。

Tooltip 原型顺序：显示来源与当前讨论 → 查看一条公开内容/一级评论 → 展开楼内回复 → 回复/@ → 查看成功回填及通知 → 接收者打开定位到对应楼内回复。加载、无内容、离线、不可见、提交中、失败重试均为原型状态。

通知导航使用类型化目标（content/thread/root/comment）及 delivery ID；打开时重新鉴权和拉取，目标收回/删除显示不可用状态。不能在系统推送载荷中携带私人笔记正文或可绕过授权的附件 URL。

## 7. REST 与本地模型接入原则

复用既有传输、鉴权、问题响应、游标和幂等机制；公开发布、收回、评论及通知事务通过业务命令实现，不暴露一组可被客户端任意拼接的数据库写操作。

| 模型组 | 私人本地/备份 | 公共服务端/缓存 |
|---|---|---|
| 内容与修订 | 私人库及密文封装，完整历史 | 仅显式发布的修订/投影 |
| 附件与关联 | 内部 ID、加密内容、私有索引 | 发布资源与当前公开关联 |
| 讨论与互动 | 待提交命令/个人 UI 状态 | 权威 thread/comment/reaction 及计数 |
| 操作与状态 | 待同步记录、并发分支、备份状态 | 幂等命令结果、业务 outbox |

不把私人 head 和全部父版本 ID 当成公共发布 API 的必传链条；公共更新检查公共版本 ETag，私人历史关系保持在加密域。公共查询不得直接读取私人数据库行作为 DTO。

正式 OpenAPI 输出应包含请求与响应 Schema、鉴权/权限、版本前置条件、幂等冲突、统一错误、稳定分页和实例。必须通过真正的 OpenAPI 解析与校验，不能因为既有 YAML 标明 3.1 就假定所有结构合规。Swagger UI 直接消费同一份文档。

### 7.1 拟新增业务命令与响应

以下为逻辑 operationId 提案，URL 最终随既有 REST 资源约定冻结；不是直接开放数据库表。

| 操作 | 最小请求语义 | 权威响应/事务约束 |
|---|---|---|
| `publishContent` / `updatePublication` | 选定内容 ID、修订的可公开快照、已就绪资源 ID、结构化 mentions/绑定、幂等键；更新带公共 ETag | publication ID、当前公共 ETag、时间、能力；公共快照+指针+绑定+outbox 同成败 |
| `withdrawContent` / `trashContent` / `restoreContent` | 内容 ID、公共状态前置条件（曾公开时）、幂等键 | 权威可见性/生命周期及版本；restore 不自动公开 |
| `createComment` / `editComment` | thread/root/reply_to、正文、mentions、所见 publication；编辑带自身 ETag | comment 与新版本、权威计数、事件身份；主题权限校验与 outbox 同事务 |
| `setReaction` | 目标与期望最终值 `like/dislike/none`，幂等键 | 当前用户反应、计数和版本；服务端从认证取 actor，原子替换同目标同账号状态 |
| `setBookmark` / `createShareLink` | 当前可见目标；收藏传最终布尔状态 | 收藏状态或受 ACL 约束的分享定位，不返回永久正文授权 |
| `beginBackupUpload` / `completeBackup` | owner 从认证推导；不透明对象 ID、密文大小/哈希、协议版本；完整依赖清单 | 限定路径上传会话；完成时校验密文对象存在及依赖闭合，再激活完整快照 |
| `getBackupDownload` / `deleteBackup` | 当前账号、备份 ID、操作前置条件 | 授权密文下载信息或可重试删除任务状态；不处理私人正文 |
| 通知正文/补拉/回执适配 | delivery ID、不透明游标、ACK 批次；按现有 Notification 端口契约 | 当前账号可见投递、持久游标和 Outcome；不能把业务 event ID 作为 ACK ID |

用户编辑尚未保存的临时状态不走公共服务端；私有备份清单敏感内容在密文内，外层只放必要传输/完整性信息。服务端只能验证密文哈希、协议和对象关系；明文语义与内容完整性由授权客户端解密后验证。

同一次 UI 操作重试保持同一幂等键；用户主动改变目标值是新操作。快速赞/踩切换在客户端按目标串行化或合并为最终待发命令，不能让旧请求的延迟重试覆盖用户新选择。跨设备并发按服务端权威版本对账。

账号映射必须复用 `Firebase UID → app_user_id/scope` 既有服务端解析；不得假设三个值相等。实际存储路径只接受服务端推导的 scope，客户端传入的 owner/path 只是待验证参数。

### 7.2 生产装配清单

- 宿主装配：账号 Provider、HTTP client、私有 Drift Repository、加密 key provider、各 channel mapper/driver、Markdown 资源 resolver、Social 关系/私信导航适配，以及 Notification 八类接入依赖按其指南逐项落实。
- Python 装配：既有身份验证/错误/幂等包装、community 命令 handler、Firestore 集合/索引与安全规则、媒体访问控制、outbox 分发与投递 API。
- 若沿用 SDK 直接同步密文 row，应纳入现有 Firebase 规则与 scope 授权测试；公共业务状态始终走 Python 命令，不准客户端直写公共指针或通知记录。普通笔记业务 REST 与既有 SDK 存储通道各自记录，不把后者冒充新 REST 接口。
- 通知和旧 outbox 的查重不足已列为补齐项；采用确定性 `(event_id, recipient_id)` 投递身份，并独立保存投递尝试状态。记录成功而推送失败必须可重试。
- 这些是模块级职责，正式执行包须继续落到实际新增文件/导出点/测试命令；本轮不修改其他子模块。

## 8. 从设计到开发的验收切分

1. 私人编辑：离线保存、重启恢复、历史差异、账号隔离；不依赖书籍 Schema 的独立笔记先验证。
2. 存储：两设备真实同步、云端密文备份与下载恢复、并发保留、中断和删除传播；只有 Fake 测试不算接通。
3. 公开：选择修订发布、私改不提前公开、版本冲突、收回后正文/历史/附件/分享全入口拒绝访问。
4. 社交：两级评论与回复、互斥赞踩、收藏/分享、资料/私信/举报/拉黑；失败回滚与幂等不重复计数。
5. 通知：同一事务产生事件、回复与 @ 去重、偏好/拉黑过滤、可靠落盘后 ACK、重启补拉和点击定位。
6. 原句与 Tooltip：待上游协议对齐，用真实重复句/改版样例证明精准锚定、同一讨论和通知回跳；不能把合成样例冒充已发布知识。

这些是纵向交付门禁，不是已 READY 的执行工作包。正式 Schema、BDD/TDD/ACT 与接口装配表在源码调研汇总后进一步冻结。
